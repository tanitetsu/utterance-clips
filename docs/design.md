# 発話クリップデスクトップアプリ — 設計正本

最終更新: 2026-11-23（Asia/Tokyo）

## 1. 目的

Windows向けデスクトップアプリで、長時間音声（目安2時間・発話正味約80分）をバッチ処理し、**発話単位の音声ファイル＋テキスト**として保存・視聴・編集できるようにする。

## 2. 非目的

- リアルタイム文字起こし
- 話者区別（ダイアライゼーション）
- 当面の Mac / モバイル対応
- 秘匿音声向けの完全オフライン必須構成（外部API利用可）

## 3. 確定要件

| 項目 | 決定 |
|---|---|
| OS | Windows |
| 処理形態 | バッチ（リアルタイム不要） |
| 文字起こし | オンライン（OpenAI） |
| 話者区別 | 不要 |
| 文の区切り | 発話区切り（短いポーズ単位） |
| 無音 | **長い無音だけ削る。区切りになる短ポーズは残す** |
| アプリ形 | **1アプリ・2画面**（処理 / 視聴） |
| タイトル | 本文先頭を仮タイトルにし、視聴画面で編集（将来AIタイトル可） |
| 視聴操作 | 一覧・上下再生・タイトル編集・削除・結合 |
| 結合 | **新規音声ファイルを追加**する（既存ファイルを上書き結合しない） |
| 想定量 | 約9本／月 |

## 4. 技術選定

| 層 | 選定 | 理由 |
|---|---|---|
| デスクトップ枠 | Electron | Windows向けUI・音声再生が作りやすい |
| 文字起こし | OpenAI（`gpt-transcribe` またはタイムスタンプが取れる同等API） | 導入容易・発話セグメント取得 |
| 音声処理 | ffmpeg（無音検出・カット・結合） | 実績が多くバッチ向き |
| 成果物メタ | フォルダ + `meta.json` | 視聴画面と処理画面で共有しやすい |

## 5. 画面方針

### 5.1 処理画面

- 音声ファイルを選択してバッチ開始
- 進捗表示（無音処理 → 文字起こし → 分割書き出し）
- 出力先フォルダを指定／デフォルト生成
- APIキーはローカル設定（リポジトリに置かない）

### 5.2 視聴画面

- 処理済みフォルダを開く
- 文一覧（タイトル＋本文）
- 上下キー（またはボタン）で前後の文を再生
- タイトル編集
- 削除
- 隣の文との結合（結果は新規ファイル）

## 6. データ方針

### 6.1 出力フォルダ例

```
meeting-2026-11-23/
  meta.json
  audio/
    001.wav
    002.wav
    ...
  audio/_archived/          # 削除・結合で外した旧ファイル（任意）
```

### 6.2 `meta.json`（概念）

```json
{
  "version": 1,
  "sourceFile": "original.wav",
  "createdAt": "2026-11-23T14:00:00+09:00",
  "segments": [
    {
      "id": "001",
      "file": "audio/001.wav",
      "title": "本日の議題は予算です",
      "text": "本日の議題は予算です。",
      "status": "active"
    }
  ]
}
```

- 視聴対象は `status: "active"` のみ
- 並び順は配列順

### 6.3 無音ルール

- **長い無音**: 削除または大幅短縮（課金・尺の削減）
- **短いポーズ**: 発話区切りとして残す（削りすぎない）
- 閾値（秒・dB）は設定可能にし、初期値は実装時に実音で調整

### 6.4 結合（必須ルール）

1. 隣接する active セグメント A, B を選ぶ
2. A+B（必要なら間に極短無音）を連結した **新規ファイル** を `audio/` に作成
3. 新しい segment を `meta.json` に挿入（Aの位置に置き、A/Bは非active化）
4. 旧ファイルは上書きせず、`_archived/` へ移すか参照だけ外す
5. 失敗時は meta もファイルもロールバック（中途半端な active を残さない）

### 6.5 削除

- `meta.json` から active を外す（または status 変更）
- 音声実体は即完全削除せず、アーカイブへ（ユーザー明示時のみ完全削除可）

## 7. 処理フロー

1. 入力音声を受け取る
2. 長無音のみ短縮（短ポーズ保持）
3. OpenAI で文字起こし（タイムスタンプ／セグメント付き）
4. 発話セグメントごとに音声を切り出し
5. タイトル = 本文先頭（短く切る）
6. `meta.json` + 分割音声を書き出し
7. 視聴画面で確認・編集

## 8. 実装時の初期値（確定）

- 文字起こし: OpenAI `whisper-1` + `verbose_json`（発話セグメントのタイムスタンプ用途）。25MB超は分割送信
- 長無音: 0.8秒以上を短縮し、0.18秒の短ポーズを残す（設定で変更可）
- 無音しきい値: -40dB
- 結合時パッド: 200ms
- APIキー: アプリ設定UI → 端末の userData に保存（リポジトリに置かない）
- 配布形式: 当面 `npm start`（インストーラは後回し）

## 9. 優先スコープ（初回リリース）

1. 処理バッチ（無音短縮 → 文字起こし → 分割保存）
2. 視聴（一覧・上下再生）
3. タイトル編集・削除・結合（新規ファイル方式）
